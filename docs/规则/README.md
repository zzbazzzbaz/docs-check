## 每份文档的结构

1. **规则一览**——**按组**列出该作用域的全部规则，含**规则编号**
2. **对象与识别**——每个对象怎么从文档里认出来（识别锚点**宽松**、与判定属性**正交**）
3. **规则详情**——**逐条**展开：对象、期望值、判定口径、边界说明
4. **不做**——明确排除的项及原因
5. **来源说明**——每条规则的依据（规范文字 / 规范样张 / 用户确认 / 外部标准）
6. **跨作用域规则**——*仅 `9-整体` 有*：整篇只读索引 `DocumentIndex` 的机制与需要它的规则清单

> 需要时可有「**待定**」小节，列尚未拍板的项。

## 两条通道

审核分两条**独立**的通道，各自产出问题，**取并集**——任一条不过即不过。

| | 通道 ① 解析通道 | 通道 ② 渲染通道 |
|---|---|---|
| 输入 | `.docx`（OOXML） | 学生本机导出的 `.pdf` |
| 读什么 | 文档的**声明**：有效格式、样式、结构、域、页面设置 | 文档的**实际版面**：几何、分页、真实字形 |
| 能判 | 字体 / 字号 / 加粗 / 对齐 / 缩进 / 行距 / 页眉页脚 / 样式 / 顺序 / 表格边框 | 分页位置、跨页、超出版心、页码连续性与正确性、行数溢出 |
| 判不了 | 任何"排完版才知道"的事 | 字体**名**——PDF 里字体被子集化 / 替换，不可靠 |
| 本轮 | ✅ 做 | ⏸ 未纳入 |

**为什么字体只在通道 ① 判**：PDF 里的字体名会被子集化（`SimSun` → `ABCDEF+SimSun`）或被替换，无法可靠判定"这是不是宋体"。字号同理。所以**字体、字号、加粗、对齐、缩进、行距一律以 docx 为准**。

**为什么分页与页码只能在通道 ② 判**：docx 里没有"页"这个概念，只有分节与分页符。实际页数、每页装了多少内容、页码显示成什么，都是**排版结果**，必须看渲染产物。

**输入从哪来**：**本轮只收 `.docx`**——学生用 WPS 编辑、保存为 `.docx` 即可。PDF 通道**暂缓**，未来再接（届时 PDF 由学生在本机用 WPS/Word 导出，服务端不放任何 office 渲染器，并用四道弱校验确认它确实来自这份 docx：文本一致性 / 元数据 / 纸张一致 / 页数合理）。

## 跨作用域规则

有一类规则**必须看全篇**才能判（如「每条参考文献都在正文中被引用过」）。它们的**归属与编号不变**，仍写在各自的作用域文档里；**机制**（整篇只读索引 `DocumentIndex` + 跨作用域判定）统一约定在 [9-整体](9-整体.md) 的「跨作用域规则」一节，附需要整篇索引的规则清单。

## 通用判定口径

适用于所有作用域。

1. **有效格式**：判定一律走 `run → 段落样式链 → Normal → docDefaults → 主题字体`，**不看 run 自身属性**。
   - 反例：`ABSTRACT` 的 run 只写了 `eastAsia=宋体`，看自身会误判"字体不是 Times New Roman"；实际 `ascii` 槽继承 `Normal` 的 Times New Roman。
2. **字体槽**：中文字体读 `eastAsia` 槽；西文/数字字体读 `ascii` 槽。
3. **空白字符不算数**：**字体类与加粗类**规则都只判**非空白字符**（空格、制表符不计）。
   - 反例一：规范样张的目录条目是 `'3.1'`（不粗）+ `' '`（加粗）+ `'系统结构的设计'`（不粗）。按"任一 run 加粗"会误报。
   - 反例二：规范样张的 `heading 2` 样式 `ascii = Arial`，但数字 `2.1` 所在 run 显式写了 Times New Roman，只有其后的空格用 Arial。按"段落级西文字体"判会误报。
4. **空段落**：段落内无文字、无图片、无域结果。bookmark 与批注锚点不算内容。
5. **可见文本**：只取正文文字，**排除域代码**（`w:instrText`）。目录条目必须这样取，否则会读到 `TOC \o "1-3"`、`HYPERLINK` 等域代码。
6. **块角色先于属性**：先判定一个段落是 标题 / 正文 / 条目 / 空行，再套规则。属性算得再准，**角色判错就是误报**。
   - **角色是全量的**：每个块都必须拿到角色；认不出的记为「未识别结构」并在报告中列出，**不许静默丢弃**——否则"学生忘了套标题样式 → 整组标题规则静默不跑"。这一条与第 9 条同源（识别失败就是问题，不是"跳过"）。
7. **识别锚点要宽松**：找对象时不要用严格文本匹配。否则学生把标题文本写错，会变成"找不到对象"，而不是**由文本规则报出错误**——该报错的地方必须报错，不能变成静默缺失。
8. **识别与判定正交**：找对象的信号，**不能是规则要检查的属性**。用同一属性既选对象又判对象 = **恒真式**，错误会静默漏掉。
   - 反例一：用「大纲级别 = 2」找附录子标题，再判「大纲级别 = 2」→ 恒真。应改用文本「附录 + 非空白字符」识别，级别交给 `APP-13`。
   - 反例二：用 `^附录[A-Z]` 识别，而 `APP-06` 要检查"必须大写" → `附录a` 永远不会被识别，也就永远报不出来。
   - **识别器是超集，判定器负责收缩**：识别宁可多收（`附录a`、`附录一` 都先认下），属性错由规则报。
9. **模块完整性前置**：顶层模块**识别不到 = 违规**（`GLB-26` / `GLB-27`，见 `9-整体`），在作用域规则**之前**判；绝不让"识别失败"变成"规则不执行"。作用域内的必需对象同理，由各作用域文档报：中文关键词行 `ABS-C-25`、Keywords 行 `ABS-E-22`、目录条目 `TOC-15`、正文五章 `TXT-51`、参考文献条目 `REF-22`、致谢正文 `ACK-12`、附录子标题 `APP-18`。
10. **禁用自动编号**：`第X章`、`[1]`、`（1）` 等编号**必须是手打的文字**。段落使用了 Word 自动编号（有效 `w:numPr` 且 `numId ≠ 0`，含经样式链继承）一律由 `GLB-28` 报出，且该段落**不再进入**依赖编号文本的规则（`TXT-19`、`REF-10`、`REF-11`、`APP-06` 等）。原因：自动编号的显示文本不在 XML 文本里，会使**文本判定**与**文本识别／分区**（`GLB-26`）全部失真。
