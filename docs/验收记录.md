## 6. 「一行数据」的成色（`NFR-4.1`）

204 条规则的属性取值方式分类（按 `Rule.prop` 的实际归属统计）：

| 类别 | 条数 | 占比 | 加一条的实际成本 |
|---|---|---|---|
| **A 纯属性数据行**（`prop=attrgetter(...)`） | **80** | 39.2% | 一个 `Rule(...)` 记录（无判定代码） |
| **B 复用 `support.py` 共享取值函数** | **84** | 41.2% | 一个 `Rule(...)` 记录（取值逻辑已共享） |
| **C 本模块自定义判定函数** | **39** | 19.1% | 需写一个判定函数（存在性 / 计数 / 结构 / 批 2） |
| **D 内联 lambda / 闭包** | **1** | 0.5% | 一行 lambda |

即 **A+B = 164 条（80.4%）的边际成本确实是一行数据**（共享选择器或取值函数），
**40 条（19.6%）需要写判定代码**——这正是需求 §7 归类里的存在性 / 计数 / 结构 / 批 2 那批。

> 诚实修正：Phase 8 计划里写「the small number of structural rules as code」，实测需要写代码的是
> **40 条，不是"少量"**。可维护性主张对**属性类规则**成立；对结构 / 存在性类规则不成立，需如实归档。

**实际例子**（源码 `rules/abstract_c.py` + 用例 `tests/rules/test_abstract_c.py`）：

```python
# 规则：一行数据，无判定代码
Rule(id="ABS-C-02", of=cjk_of(abs_c_title), prop=attrgetter("ea"),
     expect="黑体", src="规范原文：中文摘要标题三号黑体")
# 用例：命中 + 底稿合规各一行
CASE("ABS-C-02", change=ea("中文摘要标题", "仿宋"), expect_only=["ABS-C-02"])
CASE("ABS-C-02", change=None, expect_only=[])
```
