## 0. 文档约定

### 0.1 权威性排序

| 顺位 | 来源 | 作用 |
|---|---|---|
| 1 | `docs/规则/*.md` | **判定的唯一依据**。本文档与规则文档冲突时，以规则文档为准 |
| 2 | `docs/测试word/学校论文规范（有格式要求标签版）.docx` | 规范原文 |
| 3 | 用户确认 | 规则文档标注「用户确认」的条目 |
| 4 | 学校样张、真实论文 | **仅用于校准，不作判定来源** |

### 0.2 术语

| 术语 | 含义 |
|---|---|
| **作用域 / 模块** | 文档的 8 个物理分区：封面 / 中文摘要 / 英文摘要 / 目录 / 正文 / 参考文献 / 致谢 / 附录 |
| **块 / block** | 文档流里的一「段」或一「表」，按文件顺序编号 |
| **对象** | 一条规则要判的东西（某个段落、某个 run、某个表格、某个区……） |
| **有效格式** | 走「run → 段落样式链 → 默认样式 → docDefaults → 主题字体」级联之后**真正生效**的值 |
| **题注** | 图题（`图n-m …`）与表题（`表n-m …`）的统称 |
| **无法判定** | 该处存在，但解析不出值 → **不是通过** |
| **未识别结构** | 该块拿不到角色 → **不是通过** |

## 1. 背景与目标

### 1.1 问题

学校有统一的毕业论文格式规范，但学生初稿格式问题多；人工纠错有三件事做不好：**会漏**、**反复提交把老师拖垮**、**不同老师标准不一致**。

### 1.2 本期目标

把 210 条格式规则中的**前两批共 204 条**（见 §2）做成可运行的自动审核：

- 输入：学生用 WPS 编辑保存的 `.docx`
- 输出：一份**逐条、可定位、可解释**的问题清单，并**以 Word 批注的形式标进文档**（见 `FR-11`）
- 判定：**格式类属性一律以 docx 的声明为准**（字体、字号、加粗、对齐、缩进、行距、页眉页脚、页面设置、结构、编号、题注、表格边框）

### 1.3 一句话成功标准

> 学生打开标注版文档后，**不需要问「哪里错了」**——右侧批注直接告诉他：哪句话、现在是什么、应该是什么、为什么。

### 2.4 「本期不做」必须在报告里声明

不做 ≠ 不提。报告末尾必须有一节**「本轮未覆盖项」**，写明：

- 分页与页码的**实际版面效果**（`TXT-07`、`GLB-20~25` 只判 docx 层的分页标记）→ 以最终打印或 PDF 为准
- 目录页码的正确性 / 连续性 / 一致性
- 跨页表格的续表标注
- 参考文献著录格式的标点校验

**理由**：让老师与学生清楚边界，避免"系统没报 = 肯定没问题"的误解。

## 3. 判定总约定（所有规则共用，不可违反）

> 这一节是本项目的**质量红线**。每条都能对应 `docs/规则/README.md` 的「通用判定口径」，并已在对账工程里实测过：违反哪条，就会在哪个方向误报。

### 3.1 结果三态

每条规则的判定结果只有三种：

| 态 | 含义 | 报告里的样子 |
|---|---|---|
| `pass` | 判定通过 | 不出现在问题清单 |
| `fail` | 判定不通过 | 一条问题（含期望值 / 实际值 / 定位） |
| `undetermined` | **无法判定**：对象存在，但解析不出值 | 单独一栏列出，**不是通过** |

另外两条不属于三态、但同样**不是通过**：

- **对象识别不到** → 由完整性规则报出（`GLB-26` / `GLB-27` / 各区的必需对象规则）
- **块拿不到角色（未识别结构）** → 单独一栏列出

### 3.2 十项硬口径

| # | 口径 | 违反的后果 |
|---|---|---|
| 1 | **有效格式必须走级联**：run → 字符样式 → 段落样式链 → 默认段落样式 → `docDefaults` → 主题字体。**不看 run 自身属性** | 会误判学校自己的样张：`ABSTRACT` 的 run 只写了 `eastAsia=宋体`，`ascii` 实际继承 `Normal` 的 Times New Roman |
| 2 | **字体分槽**：中文字体读 `eastAsia` 槽；西文/数字字体读 `ascii` 槽 | 混判会大面积误报 |
| 3 | **只判非空白字符**：字体类、加粗类规则都不看空格与制表符 | 样张的目录条目是 `'3.1'`（不粗）+ `' '`（加粗）+ `'系统结构的设计'`（不粗），按"任一 run 加粗"会误报 4 条 |
| 4 | **西文/数字只判 ASCII 字母与数字**，**排除标点**（`. , ? ( ) / : - [ ]`） | 样张里 `.` `?` 等标点所在 run 的 `ascii` 槽是宋体，把标点算进来会误报学校样张 |
| 5 | **西文字体按字符定位到 run**，不能按段落级取 | `heading 2` 样式的 `ascii` 是 Arial，但数字 `2.1` 所在 run 显式写了 TNR → 合规；按段落级会误报 |
| 6 | **可见文本必须排除域代码**（`w:instrText`） | 目录条目会读到 `TOC \o "1-3"`、`HYPERLINK` 等，全部判错 |
| 7 | **空段落 = 无文字、无图片、无域结果**（书签 / 批注锚点不算内容） | 「后空行正好 1 个」那 9 条会集体误报 |
| 8 | **识别锚点要宽松**：找对象不用严格匹配；写错文本/空格不能变成"找不到对象" | 学生把空格写错，应该由文本规则报错，而不是静默不查 |
| 9 | **识别与判定正交**：找对象的信号不能是规则要判的属性 | 用「大纲级别=2」找附录子标题再判「级别=2」= 恒真式，级别写错永远报不出来 |
| 10 | **块角色先于属性**：先判 标题/正文/条目/题注/空行，再套规则 | 属性算得再准，角色判错就是误报 |

### 3.3 容差

「±容差」的项（纸张、页边距）容差值是**配置项**，默认值由学校样张校准后确定，**不许硬编码在规则里**。
建议默认值（待校准）：

| 项 | 容差 |
|---|---|
| 页边距 | ±0.5 mm |
| 纸张尺寸 | ±1 mm |
| 字号 | ±0.5 pt（字号应按半磅步进，实际上应精确） |
| 行距倍率 | ±0.05 |
| 缩进（字符） | ±0.05 字符 |

### 3.4 自动编号段的「让开」处理（**降级为选择器过滤，不做抑制机制**）

自动编号的**显示编号不在 XML 文本里**（排版时才生成），所以下游几条规则拿到的文本是"缺了编号"的。不处理会**给出错误的修改指令**：

| 下游规则 | 不处理会发生什么 | 性质 |
|---|---|---|
| `TXT-19` 三级以下标题 = `（1）` 形式 | 段落的可见文本里根本没有编号 → 报「不是 `（1）` 形式」 | **误报** |
| `REF-10` 编号格式 `[n] ` | 同样报「编号格式不对」 | **误报** |
| `REF-11` 编号从 1 连续 | 编号不在文本里 → 集合为空 → 报「缺号 / 跳号」 | **结论是错的** |
| `APP-06` 附录 `A,B,C` 连续 | 同上 | **结论是错的** |

**实现方式（不引入引擎级"抑制图"）**：这几条规则在取目标对象时，把"有有效自动编号的段落"过滤掉即可——

```python
# 有自动编号的段落让开，由 GLB-28 单独报出真正的问题
paras = [p for p in target_paras(scope, role="h4-") if not p.numbering]
```

`GLB-28` 负责报「该段用了自动编号，请改为手动输入编号」，其余规则让开。**几行代码，没有新概念。**

> **另一对（`REF-10` / `REF-21` 互斥）不需要任何机制**：只要两条规则**共用同一个「看起来像编号开头」的匹配器**（形如 `^[\[【［(（]?\s*\d+`），互斥就自然成立。
> **用共享匹配器代替抑制关系**，更简单也不容易错。

### 3.5 本期已决定的简化（为降低开发成本）

| 简化项 | 决定 | 代价 / 备注 |
|---|---|---|
| 规则间抑制 | **降级为「选择器过滤」**（见 §3.4），不做引擎级抑制图 | 效果不能少，机制可以省 |
| 属性值自相矛盾提示 | **不做**。判定一律按规则文档口径（**优先 `firstLineChars`**），不额外报提示 | 已知代价：`firstLineChars` 与 `@firstLine` 冲突的段落会被判"通过"，但渲染出来是错的（实测 40 篇里 1 篇 6 段）。**记入待办**，上线后若有反馈再补 |

## 4. 功能需求

### FR-1 输入与包解析

| 编号 | 需求 |
|---|---|
| FR-1.1 | 只接收 `.docx`（OOXML，zip 包） |
| FR-1.2 | 明确拒绝并给出可读原因：非 zip / 加密 / 缺 `word/document.xml` / 老式 `.doc` / 带宏的 `.docm` |
| FR-1.3 | 定位并读取所需部件：`document.xml`、`styles.xml`、`numbering.xml`、`theme/*`、`header*.xml` / `footer*.xml`、各部分的 relationships |
| FR-1.4 | 对不可信输入做防护（见 NFR-2） |

### FR-2 文档模型

解析结果必须能回答下面这些，且**每一项都能定位回原始块**：

| 编号 | 需求 |
|---|---|
| FR-2.1 | **块序列**：`w:p` 与 `w:tbl` 按文件顺序交错；内容控件（`w:sdt`）对其内容**透传**（不额外算一层块） |
| FR-2.2 | **段落**：可见文本、有效对齐、有效行距、有效缩进、大纲级别、样式名、有效自动编号 |
| FR-2.3 | **run**：文本 + 有效格式（中文字体 / 西文字体 / 字号 / 加粗 / 斜体 / 上下标） |
| FR-2.4 | **表格**：行列数、每格的**有效边框**（四边）、单元格内的段落 |
| FR-2.5 | **文本框内容**：单独一路采集（正文口径默认不下钻文本框），供 `GLB-28` 使用 |
| FR-2.6 | **分节**：页眉 / 页脚引用、页面设置（纸张、页边距）、分页标记（分节符 / 分页符 / 段前分页） |
| FR-2.7 | **域**：类型与跨度（`TOC` 域用于界定目录区） |
| FR-2.8 | **对象**：图片（`w:drawing`）、公式（`w:object` OLE 与 `m:oMath` OMML） |
| FR-2.9 | **普通表格/嵌套表格**：只把**顶层表格**计为"一个表格" |

### FR-3 有效格式（核心能力）

| 编号 | 需求 |
|---|---|
| FR-3.1 | 级联顺序：run 直接 → 字符样式 → 段落样式链（含 `basedOn`）→ 默认段落样式 → `docDefaults` → 主题字体 |
| FR-3.2 | 每个值必须带**来源标记**（是 run 直接设的？还是继承某个样式？），供报告解释 |
| FR-3.3 | 单位归一：缇 → pt；`firstLineChars`（1/100 字符）→ 字符；行距 `lineRule=auto` 时倍率 = `w:line ÷ 240` |
| FR-3.4 | **取不到值 → `None`**，不许用 `0` / `''` 冒充（那是"无法判定"，不是"不符合"） |
| FR-3.5 | 行距为 `exact` / `atLeast` 时**直接判不通过**（与"倍率"语义不同） |

### FR-4 语义定位

| 编号 | 需求 |
|---|---|
| FR-4.1 | 把文档流切成 8 个作用域，按各区标题的**关键文本**识别（去空白后比较，不要求空格 / 字体 / 样式正确） |
| FR-4.2 | 在每个作用域内**全量**判定块角色：一级标题 / 二级标题 / 三级标题 / 三级以下标题 / 正文 / 图题 / 表题 / 公式段 / 文献条目 / 空行 |
| FR-4.3 | **角色判定是全函数**：每个块都必须拿到角色；认不出的记为「未识别结构」，**进报告，不许静默丢弃** |
| FR-4.4 | 识别器是**超集**：`附录a`、`附录一`、`附录Ａ`、`第 一 章`、`第1章` 都要先认下来，写错由属性规则报 |
| FR-4.5 | 标题层级用**大纲级别 / 样式名**判，不许用字号或加粗猜 |

### FR-5 整篇索引（第二批的输入）

| 编号 | 需求 |
|---|---|
| FR-5.1 | 构建只读索引：`modules`（模块→块区间）、`chapters`(章号→块区间)、`floats`（图/表/公式登记）、`citations`（正文引用编号 + 首次出现顺序）、`toc_entries`（目录条目） |
| FR-5.2 | **索引宽松收集，规则负责收缩**：例如章候选收「文本以 `第…章` 开头」的全部，把大纲级别一并带上，由规则收缩 |
| FR-5.3 | 抽不到就**显式「无法判定」**，不许静默通过 |
| FR-5.4 | 索引必须有自检（见 FR-10） |

### FR-6 规则执行

| 编号 | 需求 |
|---|---|
| FR-6.1 | 规则以**数据**声明：`规则号 + 对象选择器 + 属性 + 期望值 + 依据`。属性类是数据行，不是函数 |
| FR-6.2 | 每条规则可**单独触发、单独统计命中数** |

### FR-8 第二批规则（7 条）

#### FR-8.1 `TXT-49` 三线表

| 项 | 要求 |
|---|---|
| 对象 | 文档里的**每个顶层表格** |
| 期望 | 只有三条线：**上框线、下框线、表头行下框线**；**无竖线、无其他内横线** |
| 判定 | 先算每个单元格四边的**有效边框**，再按上面的期望判 |
| 有效边框口径 | 单元格**直接写的** `tcBorders` 优先；没写的，按**位置**取表级对应边：<br>上 → 首行取表 `top`、其余取 `insideH`；下 → 末行取表 `bottom`、其余取 `insideH`；左/右 → 首列取 `left`、末列取 `right`、其余取 `insideV` |
| 表级值 | 表直接写的 `tblBorders` 覆盖表格样式（含 `basedOn` 链）的 `tblBorders` |
| 「有线」判据 | 边框元素存在且 `w:val` 不是 `none`/`nil` |
| 已知限制 | 若某表的线**只由表格样式的条件格式**（`tblStylePr`，例如 `firstRow` 表头线）提供，判定要标注「依据表格样式判定」，并且**不能当成确定结论**（实测 WPS 不体现这类线） |
| 边界 | 单行表 / 单列表的"内部边"不存在，不做要求 |

> **为什么口径要写这么细**：实测按「单元格直接继承表级同名边」实现，表格**下框线**只有 64.5% 与渲染器一致；换成上面的**位置映射**口径后，四边 100% 一致。这条口径错了，三线表会大面积误判。

#### FR-8.2 `TXT-52` 公式编号正确性

| 项 | 要求 |
|---|---|
| 对象 | 公式编号 `(章号-序号)` |
| 期望 | 章号 = 公式**所属一级标题**的章号（中文数字 → 阿拉伯数字，要认 `第3章` 这种阿拉伯写法）；序号 = 该公式在本章内的次序，**从 1 起连续，不跳号、不重复** |
| 判定 | 按一级标题把公式分章；章号不符报出；每章内序号集合须恰为 `{1, 2, …, N}` |
| 依赖 | `chapters` + `floats.formula` |

#### FR-8.3 `TXT-36` / `TXT-42` / `TXT-48` 必须有引用

| 项 | 要求 |
|---|---|
| 对象 | 每个公式 / 每个图 / 每个表 |
| 期望 | 正文里出现过它的编号引用：公式 `式(n-m)` 或 `(n-m)`；图 `图n-m`；表 `表n-m` |
| **搜索范围** | 正文区的**普通段落**。**必须排除**：题注段落自身、公式段、表格内部段落、目录区 |
| 为什么要排除 | 若不排除题注自身，`图3-1` 永远能在图题里找到 → **恒真式**，规则永远不报 |

#### FR-8.4 `REF-14` / `REF-15` 正文引用与顺序

| 项 | 要求 |
|---|---|
| 输入 | 正文的引用标注集合 `C` 与**首次出现顺序** |
| `REF-14` | `R \ C`（有条目、正文没引用）→ 报出。`C \ R`（悬空引用）**不报**（属正文/整体作用域） |
| `REF-15` | 按首次出现顺序排出的编号序列 `S` 与 `1…N` 比对，**报首个倒置位置** |
| 无法判定 | 正文区抽取失败或引用标注识别不出 → **显式输出「无法判定」，不许静默通过** |

> **⚠️ 前置问题（列入 §7 待确认）**：规则文档把「引用标注」的识别锚点定为**上标**，而 `TXT-30` 判定的又是"必须上标"——**用上标找对象再判上标 = 恒真式**，违反 §3.2 第 9 条。
> 建议改为：识别锚点 = 可见文本匹配 `^\[(\d+([,，-]\d+)*)\]$` 的 run（**不管上不上标**，超集）；`TXT-30` 判其中**没上标**的；`REF-14/15` 用整个集合（宁可宽）。
> 不改的话，学生忘了上标会让 `TXT-30` 静默漏报，并连带 `REF-14/15` 大面积「无法判定」。

### FR-9 定位与报告

#### FR-9.1 定位（**报告与批注共用同一套定位**）

内部块号对学生没用——"第 237 段"在 Word 里找不到，而且不同软件的段落计数还不一样（实测 WPS 会**在每个表格行末多算一个空段**）。所以定位分两层：

| 层 | 字段 | 用途 |
|---|---|---|
| **机器层** | `block_id`（按文件顺序）+ `run_index` + **XML 元素引用** | 批注回写、结果复现。元素引用**必须在解析时保留**（现在解析完就扔了，留着的成本是零） |
| **人类层** | `module`（作用域）+ `chapter` / `section`（所属章 / 节）+ 区段内段序 + **本段文字摘要** + **问题涉及的字符片段** | 报告里给人看，要能**用搜索找到** |

报告条目的定位必须长这样：

```
【TXT-02】正文 › 第三章  系统设计（章标题）
  中文字体：现在是「仿宋」，应为「黑体」      依据：规范原文「一级标题：黑体，三号」
  怎么找：在文档里搜「第三章  系统设计」

【TXT-26】正文 › 第三章 › 3.2 系统架构（该节第 3 段）
  片段：…本系统采用『Spring Boot』三层架构…
  西文和数字字体：「Spring Boot」现在是「Arial」，应为「Times New Roman」
```

### FR-11 批注回写（把问题标进文档）

**目标**：产出一份 `原文件名.已标注.docx`，学生用 WPS / Word 打开后**在右侧看到逐条批注**，点一下跳到出问题的位置。**原文件不改动。**

#### FR-11.1 基本做法

在文档 XML 的目标位置插批注标记，并写入批注正文部件：

```xml
<w:p>
  <w:commentRangeStart w:id="3"/>
  <w:r><w:t>第三章  系统设计</w:t></w:r>
  <w:commentRangeEnd w:id="3"/>
  <w:r><w:commentReference w:id="3"/></w:r>
</w:p>
```

另需：`word/comments.xml`（批注正文）、`[Content_Types].xml` 注册部件、`word/_rels/document.xml.rels` 增加关系。

#### FR-11.2 锚定粒度

| 问题粒度 | 锚在哪 |
|---|---|
| 段落级（对齐 / 行距 / 缩进 / 后空行 / 文本） | **整段**（首 run 之前 → 末 run 之后） |
| run 级（字体 / 字号 / 加粗 / 上标） | **默认与同段的其他问题合并成一条批注**；批注正文里**指出具体字符片段**（如「『Spring Boot』这几个字」） |
| 表格 | 锚在该表**第一个单元格的第一段** |
| 页眉 / 页脚 / 页面设置 / 节级 | **不能批注**（Word / WPS 不支持）→ **只进报告**，报告里注明"位于页眉/页脚，无法批注" |
| 文本框内 | 锚在文本框的**宿主段落**，批注正文注明"在文本框内" |
| 模块缺失（`GLB-26`） | 锚在"该模块应在位置"的前一个模块末尾；实在无可锚位置则只进报告 |

**默认按「段落 / 对象」聚合成一条批注**（一个对象上的多条问题合并，正文里编号列出）——否则一个段落挤 5 条批注，Word 里读不了。可提供"每条问题一条批注"的开关。

#### FR-11.3 批注正文

- 白话，说明"哪里 / 现在是什么 / 应该是什么"；
- 结尾附**规则号 + 依据**；
- **长度上限 200 字**（超长 Word 显示不全）→ 截断并注明"详见报告"；
- 作者名建议 `格式审核`，带时间戳；
- 清掉 XML 非法字符。

#### FR-11.4 硬约束

| 编号 | 约束 |
|---|---|
| FR-11.4.1 | **只插批注标记，不改动任何正文内容**：标注版与原文档的正文文字必须**逐字一致** |
| FR-11.4.2 | 解析与写回必须操作**同一棵 XML 树**（不许解析 A、写 B） |
| FR-11.4.3 | 批注标记必须成对、嵌套正确；**只批在单段内**，不跨段 |
| FR-11.4.4 | 批注 `id` 全局唯一，顺序按文档顺序 |
| FR-11.4.5 | 锚点找不到安全位置时 → **降级为报告条目**，不许丢问题，也不许产出坏文件 |
| FR-11.4.6 | 目标文档**已带批注**时追加，不覆盖（`id` 从已有最大值之后开始） |
| FR-11.4.7 | 产出文件必须能被重新解析（见 `FR-11.5`） |

#### FR-11.5 自检（四道闭环）

1. **文字核对**：插批注前断言"计划批的那段文字" == "XML 里那段文字"（防元素引用错位）
2. **数量核对**：批注数 == 聚合后的问题数；降级项**单独计数**
3. **内容不变**：写回后重新解析，断言正文文字与原文档**逐字一致**
4. **锚点回读**：重新解析标注版，断言每条批注锚定的文字 == 该问题所在对象的文字

（另加**人工抽检**：随机若干篇在 WPS 里打开，确认批注位置与内容。）

#### FR-11.6 兼容与兜底

- WPS / Word 的现代版本都能读 `word/comments.xml`，但**版本差异存在**；
- **报告始终是兜底**：批注打不开也不影响审核结论；
- 若某类问题系统性无法批注（页眉页脚等），报告里要有**汇总说明**，而不是悄悄消失。

## 附录 D. 规则文档与代码的一致性维护

1. **规则文档是权威源**：`docs/规则/*.md` 先改，代码后改。
2. **规则号双向一致**：从规则文档抽取的规则号集合，与代码注册的规则号集合**必须完全相同**（CI 强制）。这条能根治"文档改了代码没改"。
3. **规则号连续**：每个作用域内的编号连续；移除某条规则后，其后的编号顺延补齐，全库引用同步更新。
4. **每条规则的"依据"必须可追溯**：规范原文 / 样张 / 用户确认 / 外部标准，四选一并标注。
5. **口径变更要留痕**：判定口径变化时，在规则文档里记录旧口径与新口径，避免"同一份论文两次审核结论不同"说不清。
