## 2. 分层设计

### 2.1 五层

```
 .docx
   │
   ▼
┌───────────────────────────────────────────────────────────┐
│ L1 parse       解包 / 部件 / 文档模型 / 有效格式            │  ← 唯一碰 OOXML 的地方
└───────────────────────────────────────────────────────────┘
   │  Doc（不可变内存对象）
   ▼
┌───────────────────────────────────────────────────────────┐
│ L2 semantics   作用域分区 · 块角色 · 具名选择器 · 共享匹配器 │
└───────────────────────────────────────────────────────────┘
   │  带 (scope, role) 的块
   ▼
┌───────────────────────────────────────────────────────────┐
│ L3 index       整篇索引 DocumentIndex + 索引自检            │
└───────────────────────────────────────────────────────────┘
   │
   ▼
┌───────────────────────────────────────────────────────────┐
│ L4 rules       数据驱动判定 → 问题清单                      │
└───────────────────────────────────────────────────────────┘
   │  list[Issue]
   ▼
┌───────────────────────────────────────────────────────────┐
│ L5 report      issues.json · report.html · 批注写回          │
└───────────────────────────────────────────────────────────┘
```

### 2.2 每层的职责与禁忌

| 层 | 只做什么 | **禁止** |
|---|---|---|
| **L1 parse** | 读 XML，产**事实**；算有效格式 | 出现任何判定逻辑（`if font != "宋体"` 一律不许出现在这层） |
| **L2 semantics** | 分区、定角色、提供选择器 | 取属性值、判对错 |
| **L3 index** | 收集跨篇事实 | 判定。索引只收集，规则负责收缩 |
| **L4 rules** | 按数据判定、生成 `Issue` | **`import lxml`**；读 XML；硬编码段号 / 文件名 |
| **L5 report** | 渲染 + 写批注 | 重新判定、修改结论 |

### 2.3 依赖方向与强制执行

只能自上而下依赖：`report → rules → index → semantics → parse`。

**用工具锁死，不靠自觉**（`.importlinter`）：

```ini
[importlinter]
root_package = thesischeck

[[contracts]]
name = 分层依赖必须单向
type = layers
layers =
    thesischeck.report
    thesischeck.rules
    thesischeck.index
    thesischeck.semantics
    thesischeck.parse

[[contracts]]
name = 规则层、语义层、索引层不许碰 XML
type = forbidden
source_modules =
    thesischeck.rules
    thesischeck.semantics
    thesischeck.index
forbidden_modules = lxml
```

CI 里跑 `lint-imports`。

> **为什么这两条契约比一百行注释有用**：需求文档承诺"加一条规则 ≤ 1 行数据"，这个承诺只有在 L4 完全不碰 XML 时才成立。一旦有人为了方便直接去 XML 里抠，两周后规则层就是一坨泥——而 CI 会在第一次违反时就拦住。

## 3. 冻结的接口

架构的稳定性 = **冻结的接口少而硬**。只冻结下面 5 个，其余随便改。

### 3.1 文档模型（L1 的唯一产物）

```python
from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class Run:
    text: str
    ea: str | None            # 中文字体（有效值）。None = 取不到（≠ 不符合）
    west: str | None          # 西文字体（有效值）
    sz: float | None          # pt
    bold: bool | None
    italic: bool | None
    va: str | None            # superscript / subscript
    index: int                # 段内 run 序号
    xml: object               # lxml 元素引用 —— 批注回写靠它

@dataclass(frozen=True, slots=True)
class Para:
    id: int                   # 块号，按文件顺序，当次有效
    story: str                # main / textbox
    scope: Scope              # L2 填
    role: Role                # L2 填；认不出 = Role.UNKNOWN
    text: str                 # 可见文本（已排除 w:instrText 与 Word 控制符）
    style: str                # 样式名（不是 styleId）
    outline: int | None       # 大纲级别
    align: str | None         # center / both / left / right
    line: float | None        # 行距倍率
    line_rule: str            # auto / exact / atLeast
    first_line_chars: float | None
    left_chars: float | None
    numbering: NumPr | None   # **有效**自动编号（含样式链继承）
    runs: tuple[Run, ...]
    xml: object
```

另有 `Table` / `Section`（页眉页脚引用 + 页面设置）/ `Box`（文本框）/ `Field` / `Object`（图片、公式）。

**约定**：
- 全部 `frozen=True, slots=True`（只读、省内存）
- **取不到值一律 `None`**，不许用 `0` / `""` 冒充 —— `None` 是"无法判定"，不是"不符合"
- 每个对象都带 `xml`（元素引用），这是批注回写与调试的锚点；留着它零成本

### 3.2 角色与选择器（L2）

```python
class Role(StrEnum):
    H1 = "h1"; H2 = "h2"; H3 = "h3"; H4 = "h4-"       # 三级以下（（1）（2）…）
    BODY = "body"
    CAPTION_FIG = "fig"; CAPTION_TAB = "tab"; FORMULA = "formula"
    REF_ITEM = "ref"; EMPTY = "empty"
    UNKNOWN = "unknown"        # 认不出 → 进报告「未识别结构」，**不是通过**

class Scope(StrEnum):
    COVER = "cover"; ABS_C = "abs_c"; ABS_E = "abs_e"; TOC = "toc"
    BODY = "body"; REFS = "refs"; ACK = "ack"; APPENDIX = "appendix"
```

**选择器：对象识别的唯一出处。** 需求文档里那几条最容易写错的口径，全部落在这一层，只实现一次：

```python
BODY_PARA  = sel(Para, role=Role.BODY)
H1_TITLE   = sel(Para, role=Role.H1)
H4_NO_AUTO = sel(Para, role=Role.H4, where=lambda p: not p.numbering)   # §3.4 的「让开」
EAST_CHARS = sel(Run, where=has_cjk)           # 只判中文字符所在的 run
WEST_CHARS = sel(Run, where=has_ascii_alnum)   # 只判 ASCII 字母数字，排除标点
REF_ITEM   = sel(Para, role=Role.REF_ITEM)
```

配套 `matchers.py` 放**共享匹配器**（形如"看起来像编号开头"），保证 `REF-10` 与 `REF-21` 天然互斥：

```python
def looks_like_number(text) -> bool:      # ^[\[【［(（]?\s*\d+
def chapter_text(text) -> bool:           # 第X章 / 第 一 章 / 第1章（超集）
def appendix_sub(text) -> bool:           # 附录 + 非空白字符（附录a / 附录一 都算）
def figure_caption(text) -> bool:         # ^图\d+-\d+
```

> **这是整套设计里最划算的一处**：口径 3（只判非空白）、4（只判字母数字）、5（按字符定位到 run）全部变成选择器里的一行；"识别宽松、识别与判定正交"也从纪律变成结构。

### 3.3 规则与结果（L4）

```python
from operator import attrgetter

EA   = attrgetter("ea")
SZ   = attrgetter("sz")
LINE = attrgetter("line")

# 一条属性类规则的全部内容
Rule(id="TXT-25", of=BODY_PARA, prop=EA, expect="宋体", src="规范原文：小四号宋体")

@dataclass(frozen=True, slots=True)
class Issue:
    rule: str
    verdict: Verdict                       # FAIL / UNDETERMINED（PASS 不进报告）
    where: Para | Run | Table | Section
    got: Any
    expect: Any
    src: str                               # 依据：规范原文 / 样张 / 用户确认
    loc: Location                          # 见 3.5

def run(doc: Doc) -> list[Issue]:
    """引擎：就这么长，不需要更多。"""
    ctx = Ctx(doc)
    out: list[Issue] = []
    for r in REGISTRY:
        for obj in r.of(ctx):
            got = r.prop(obj)
            if got is None:
                out.append(Issue(r.id, Verdict.UNDETERMINED, obj)); continue
            if not COMPARE[r.cmp](got, r.expect):
                out.append(Issue(r.id, Verdict.FAIL, obj, got, r.expect, r.src, locate(obj)))
    return out
```

比较器只需要 5 个：`eq` / `approx`（带容差）/ `regex` / `in_set` / `count_range`。

**规则数据放代码，不放 YAML**：期望值、容差、规则号都是常量，写在代码里有类型检查、能复用枚举、少一层解析。**规则文档是给人看的，代码里的数据表是机器执行的，两者由一致性测试锁住**（需求 `NFR-4.2`）。

### 3.4 批注写回（L5）

```python
def annotate(doc: Doc, issues: list[Issue]) -> bytes:
    """把问题按对象聚合，写成 Word 批注，返回新的 docx 字节；原文件不动。"""
```

细节见需求文档 `FR-11`；实现上只有一点要在这里强调：**必须操作 L1 交出来的那棵树**，不是重新解析一棵。

### 3.5 定位（`Location`）

```python
@dataclass(frozen=True, slots=True)
class Location:
    # 机器层
    block_id: int
    run_index: int | None
    # 人类层（报告里给人看）
    scope: Scope
    chapter: str | None          # 「第三章  系统设计」
    section: str | None          # 「3.2 系统架构」
    nth_in_scope: int            # 该区段内的段序
    excerpt: str                 # 本段文字摘要（≤40 字）
    span: str | None             # 问题涉及的字符片段（run 级问题）
```

### 3.6 接口变更纪律

- 冻结的 5 个接口要改 → **升 `major`**，并在 PR 里说明影响
- 文档模型加字段 → 允许（只增不改）
- **不许**为了某一条规则给模型加专用字段；规则有自己的数据表

## 4. 有效格式与按需回溯

### 4.1 级联顺序（L1 的核心资产）

```
run 直接  →  字符样式  →  段落样式链（含 basedOn）  →  默认段落样式  →  docDefaults  →  主题字体
   高  ←───────────────────────────────────────────────────────────────────────  低
```

单位归一：

| 源 | 换算 |
|---|---|
| `w:sz` | ÷2 → pt |
| 缩进缇值 | ÷20 → pt |
| `w:ind/@firstLineChars` | ÷100 → 字符（**优先**） |
| `w:spacing/@line` + `lineRule=auto` | ÷240 → 倍率 |
| `lineRule=exact/atLeast` | 不换算，**直接判不通过** |

### 4.2 按需回溯（D2）

**判定时不记来源；只有"判不通过"时，才对该属性重走一次级联并把路径记下来。**

```python
def resolve(chain, prop, trace: list[str] | None = None):
    """取值。传入 trace 时，沿途记录每一环的名字。"""
```

**关键约束：取值与回溯必须是同一份代码**（同一个 `resolve`，只是多传一个 `trace`）。绝不允许写第二份"查来源"的实现——两份实现一定会在某个边界上分叉。

产出长这样（报告里的"怎么改"就靠它）：

```
中文字体：现在是「仿宋」（run 上直接设置），应为「黑体」（依据：规范原文「一级标题：黑体，三号」）
```

来源的取值：`run` / `字符样式:xxx` / `样式:heading 1` / `默认段落样式` / `docDefaults` / `主题字体`。

| YAML / TOML 规则表 | 见 §3.3——规则数据放代码，除非将来真要让非程序员改规则 |

## 7. 解析器重写方案（D1）

### 7.1 从哪抄、抄什么

`test2/docxfmt/own*.py` 共 **1304 行**，是逐条对账验证过的（84 个字段 / 421704 次比对 / 一致率 99.999%）。重写时**逐模块对照**：

| test2 | 转正后 | 抄什么 | 改什么 |
|---|---|---|---|
| `own.py`（679 行） | `parse/document.py` + `effective.py` + `model.py` | 级联逻辑、文本提取规则、对象识别 | 产物从 `dict` → `dataclass`；加类型；拆模块 |
| `own_pages.py`（154） | `parse/section.py` | 分节、页眉页脚继承、页面设置 | 同上 |
| `own_textbox.py`（85） | `parse/document.py`（box） | `mc:Fallback` 去重、宿主段落映射 | 同上 |
| `own_borders.py`（150） | `parse/document.py`（border） | **按位置映射**的边框口径 | 同上 |
| `index.py`（236） | `index/document_index.py` | modules / chapters / floats / citations / toc_entries | 保留"宽松收集"纪律 |

**抄的是逻辑，不是结构。** test2 的代码是为对账写的：函数长、返回 dict、少抽象。转正后要类型化、拆开、去掉对账相关的分支。

### 7.2 等价性验证（这一步让重写不冒险）

**做法**：新解析器加一个**只用于调试的开关**，能产出**与 test2 同构的 JSON**：

```
python -m thesischeck --compat-dump 论文.docx > new.json
diff <(jq -S . new.json) <(jq -S . test2/out/论文.own.json)
```

40 篇逐字段比对，**必须零差异**（有差异要能逐条解释）。这是"重写有真值可校"的关键。

> ✅ **已办**：快照已 gzip 进 `test2/snapshots/`（49MB → 4.6MB，commit `c97eaaf`）。
> 用 `./test2/snapshots.sh unpack` 还原到 `out/` 再 diff；`compat-dump` 也可以直接读 `.gz`。

### 7.3 重写顺序

```
1. package.py   解包 + 安全防护           （无依赖，先做）
2. model.py     冻结模型                   （定契约）
```

## 8. 服务形态（D3）

### 8.1 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/` | 单页 HTML（上传 + 结果 + 下载） |
| `POST` | `/api/review` | 上传 `.docx`，**同步**返回结果摘要 + 3 个下载地址 |
| `GET` | `/api/review/{job}/issues.json` | 机器可读问题清单 |
| `GET` | `/api/review/{job}/report.html` | 人类可读报告 |
| `GET` | `/api/review/{job}/marked.docx` | 标注版文档（批注） |

`POST /api/review` 的返回：

```json
{
  "job": "8f3c…",
  "summary": {"fail": 12, "undetermined": 3, "unrecognized": 1, "by_scope": {"正文": 7, "参考文献": 5}},
  "uncovered": ["分页与页码的实际版面效果", "目录页码的正确性/连续性"],
  "downloads": {
    "issues": "/api/review/8f3c…/issues.json",
    "report": "/api/review/8f3c…/report.html",
    "marked": "/api/review/8f3c…/marked.docx"
  }
}
```

### 8.2 实现要点

| 要点 | 做法 |
|---|---|
| **不要阻塞事件循环** | 端点写成 `def`（不是 `async def`）→ FastAPI 自动丢线程池；**解析是同步 CPU 代码，写成 `async def` 再直接调用会卡住整个服务** |
| 同步还是异步 | **同步**。单篇 0.09 秒（最坏 3 秒），套一层"任务队列"是过度设计 |
| 临时产物 | `job id` → 临时目录，**保留 1 小时**，启动时清理过期；**不落数据库** |
| 单 HTML | 原生 `fetch` + `FormData`，无 npm、无构建。展示三态统计 + 问题列表 + 三个下载按钮 + **未覆盖项声明** |
| 文案 | 面向学生，不出现 XML、`eastAsia`、`w:sz` 这类词 |

### 8.3 安全（上传的文件是**不可信输入**）

| 威胁 | 对策 |
|---|---|
| XXE / 十亿笑 | lxml：`resolve_entities=False`、`no_network=True`、`huge_tree=False` |
| zip bomb | 限制条目数 / 解压总大小 / 压缩比 |
| 路径穿越 | 只取文件名的 `basename`；落盘用**随机名**；拒绝条目名含 `..` |
| 超大文件 | 请求体大小上限（建议 50 MB），流式读 + 限长 |
| 超时 | 解析加超时（建议 30 秒） |
| 加密 / 带宏 / 老 `.doc` | 明确拒绝，返回可读原因 |
| 顺带 | 默认只监听 `127.0.0.1`；不访问文档里的任何 URL |

### 8.4 部署

`uv` + `uvicorn`，单进程足够（0.09 秒/篇）。需要横向扩展时再加进程数——**不要提前上容器编排**。

## 9. 测试策略

**反目标**：不追求行覆盖率。追求两件事：**每条规则有正例 + 反例**，**每条口径有测试**。

### 9.1 五层

| # | 层 | 测什么 | 数据 | 速度 |
|---|---|---|---|---|
| 1 | **单元** | 级联（每个槽 × 每个来源层级）、单位换算、选择器、比较器 | 手写最小 XML 片段，**不需要 docx** | 毫秒 |
| 2 | **规则** | 每条 2 个：命中 / 通过（§9.2） | 全合规底稿 + 偏差声明 | 秒 |
| 3 | **不变量** | 块覆盖、区间连续、角色覆盖率、编号唯一、引用顺序 | 每篇语料 | 秒 |
| 4 | **金标准快照** | 全流程结果 diff | 样张（进 git）+ 真实论文（本地） | 分钟 |
| 5 | **批注闭环** | FR-11.5 四道断言 + 往返一致 | 语料 + 构造的坏锚点 | 秒 |
| *开发期* | WPS 校准 | 与 WPS 真值对账 | `tools/wps_calibrate/`，**手动触发** | 十几分钟 |

### 9.2 关键技巧：「全合规底稿 + 偏差声明」

这是让 **204 条规则**变便宜的支点：

```python
# tests/rules/test_abstract_c.py —— 每条规则就这么两行
CASE("ABS-C-02", base=BASE, change=ea("中文摘要标题", "仿宋"), expect_only=["ABS-C-02"])
CASE("ABS-C-12", base=BASE, change=text("中文关键词行", "关键词;"), expect_only=["ABS-C-12"])
```

| 元素 | 作用 |
|---|---|
| `base` | 一份**手工造的全合规论文**（跑出来零问题、零无法判定） |
| `change` | 声明式改一处：改哪个对象的哪个属性 |
| **`expect_only`** | **精髓**：断言"**只**报这一条" —— 能抓规则互相干扰、以及"改一处引发别处误报" |

**全合规底稿怎么做（D4 相关）**：**手工造一份最小全合规论文**，不用学校规范 docx 当底稿 ——
后者本身可能带着一堆问题（它的任务是"说明规范"，不是"当合规样本"），清它的时间比造一份新的还长。
学校那两个规范 docx 作为**语料**保留，不作为底稿。

### 9.3 反恒真测试（专治需求文档点名的坑）

| 用例 | 断言 |
|---|---|
| `附录A` 大纲级别 2 → 3 | **仍被识别**为子标题 + `APP-13` 命中 |
| `附录A` → `附录a` | **仍被识别** + `APP-06` 命中 |
| 删掉正文里的 `图3-1` 引用 | `TXT-42` **能报出来** |
| 段落加自动编号 | `GLB-28` 命中，且 `REF-10` / `REF-11` **不报** |
| 段落**完全不以编号开头** | `REF-21` 命中，`REF-10` **不报** |

这类测试写起来便宜，但它是唯一能证明"规则真的会报"的东西。

### 9.4 快照纪律

- 快照**按规则号排序**后落盘，避免遍历顺序变化产生噪音 diff
- 快照内容 = `issues.json` 的规范化版本（去掉时间戳 / 路径 / 耗时）
- CI 里**不阻塞合并**，但要在 PR 里贴出来 —— **diff 必须有人看才算回归保护**

### 9.5 CI 流水线

```
1. ruff check  +  ruff format --check
2. mypy --strict
3. lint-imports                       ← 分层契约（§2.3）
4. pytest tests/unit tests/rules tests/invariants tests/annotate   （快，目标 < 30 秒）
5. pytest tests/golden                ← 样张 + 快照 diff（输出贴到 PR）
6. 手动触发：tools/wps_calibrate      ← 不与常规 CI 混跑
```

## 10. 语料管理（D4）

### 10.1 分层

| 层 | 内容 | 进 git？ | 用途 |
|---|---|---|---|
| **A 合成样张** | 全合规底稿 + 每条规则的偏差变体（程序生成） | ✅ 进 | 规则测试（§9.2 的 `base`） |
| **B 学校材料** | 规范原文 docx + 样张 docx | ✅ 进（小） | 口径校准、验收 |
| **C 真实论文** | 40 篇学生论文 | ❌ **不进** | 金标准快照、等价性验证 |
| **D 真值快照** | `test2/snapshots/*.json.gz`（490 个，4.6MB） | ✅ 进 | **等价性验证基线**（§7.2） |

### 10.2 C 层怎么用

- 放在**仓库外的固定目录**，用环境变量指：`THESIS_CORPUS_DIR=/path/to/corpus`
- 测试里 `@pytest.mark.skipif(not corpus_available())` —— 本地跑全量，CI 只跑 A/B
- 每篇配一个 `.sha256`，防止"不小心换了文件导致快照全变"

### 10.3 命名与脱敏

- 真实论文：**文件名脱敏**（`real-001.docx`），保留一份映射表在仓库外
- 快照里的文本摘要要做长度截断（≤40 字），避免把整段正文写进仓库

## 11. 错误处理与分层异常

```python
class ThesisCheckError(Exception): ...
class BadDocument(ThesisCheckError): ...     # 用户可读：非 docx / 加密 / 损坏 / 超限
class ParseError(ThesisCheckError): ...      # 解析失败（附部件与位置）
class RuleError(ThesisCheckError): ...       # 单条规则异常
```

三条纪律：

1. **坏文件不崩**：`BadDocument` 转成可读提示（不是 500 / 堆栈）
2. **单条规则异常不中断整篇**：捕获 → 该规则记为失败 → 继续跑其余规则 → 报告里标注"该规则未能执行"
3. **宽容解析要记账**：不认识的 XML 结构不抛异常，但**必须记进清单**（`FR-10.4`），否则"没报"就等于"没查"

## 15. 本设计防的是什么（自查表）

| 设计点 | 防的问题 |
|---|---|
| 五层单向依赖 + import-linter | 规则层慢慢长成一坨泥，"加一条规则"越来越贵 |
| 角色全量 + `UNKNOWN` 进报告 | 学生忘套样式 → 整组规则静默不跑 |
| 选择器承载口径 3/4/5 | 同一条口径在不同规则里实现不一致 |
| 共享匹配器 | `REF-10` / `REF-21` 打架（同一段报两条） |
| `None` = 无法判定 | 把"取不到"当成"不符合"，产生幽灵问题 |
| `expect_only` 断言 | 规则互相干扰、改一处引发别处误报 |
| 反恒真测试 | `TXT-42` 这类"必须有引用"写成永远通过 |
| 等价性验证（40 篇零差异） | 重写解析器引入退化 |
| 批注四道闭环 | 批注错位 / 把文档写坏 |
| 只插标记不改内容 | 系统"顺手"改了学生的文档 |
| 报告三态分区 + 未覆盖项 | 老师把"无法判定"当成"通过" |
