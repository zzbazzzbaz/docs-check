## 对象与识别

| 对象 | 识别方式 |
|---|---|
| 附录标题 | 可见文本**去掉内部空白后**等于 `附录`；样张中大纲级别为 1 级（`heading 1`） |
| 附录子标题 | 可见文本匹配 `^附\s*录\s*\S`（「附录」后还有非空白字符），如「附录A名词术语及缩略词」；样张中大纲级别为 2 级（`heading 2`） |
| 附录编号 | 附录子标题文本中的「附录」+ 其后的字符（正误由 `APP-06` 判） |
| 附录正文 | 附录区内、**既不是附录标题、也不是附录子标题、也不是图表题注**的非空段落 |

> **识别锚点要宽松，且与判定属性正交**（见 README「通用判定口径」第 8 条）：子标题按「**附录 + 非空白字符**」识别，
> - **不依赖大纲级别** → 学生忘了套 `heading 2` 时仍会被识别，由 `APP-13` 报级别错误；
> - **不要求 `[A-Z]`** → 写成 `附录a` / `附录一` / `附录Ａ` 时仍会被识别，由 `APP-06` 报编号错误。
>
> 只有**一个 `附录X` 都识别不到**时，才由 `APP-18` 报"子附录缺失"；「附    录」标题整个没有则由 `9-整体` 的 `GLB-26` 报。

### ⚠️ 附录正文必须排除附录子标题

规范样张里：

```
'附    录'                    heading 1   黑体 / 三号 / 居中           （附录标题）
'附录A名词术语及缩略词'        heading 2   黑体 / 四号 / TNR / 无缩进    （附录子标题）
'论文的附录用大写字母A，B…'    正文        宋体 / 小四 / TNR / 缩进 2 字符 （附录正文）
```

**旧系统把「附录A名词术语及缩略词」（附录子标题）当成"附录正文"来查**，报了 4 条错（字号 14pt、中文字体黑体、西文字体 Arial、首行缩进 0），**全是误报**。

> 注：附录子标题自身另有 `APP-13 ~ APP-17` 规则。样张原先 `heading 2` 的 `ascii=Arial`，`附录A` 的 `A` 会命中 `APP-16`；**已于 2026-09-25 在样张（两个 `.docx`）上把该 run 的 `ascii`/`hAnsi` 显式改为 Times New Roman**，故样张现与 `APP-16` 一致。`heading 2` 样式本身仍为 `Arial`，靠 run 级显式值覆盖。

→ 附录正文规则的适用对象必须**先做块角色判定**（附录标题 / 附录子标题 / 图表题注 / 正文），再套规则。

## 规则详情

### APP-18 · 存在性

- **对象**：附录区
- **期望**：附录区内至少有 **1 个附录子标题**（`附录X` 形式）
- **判定**：按宽松锚点（`^附\s*录\s*\S`）统计附录区内的子标题数；**为 0** 时报出
- **报告口径**：`未识别到附录子标题，请检查是否按「附录A」「附录B」形式书写`
- **依据**：规范原文"论文的附录用大写字母A，B，C等连续编号，如附录A"
- **说明**：
  - 只判"**有没有**"，不判"对不对"——编号大小写 / 字母序由 `APP-06` 判、级别由 `APP-13` 判
  - 识别宽松：`附录a`、`附录一`、`附录Ａ` 都算"存在"，不会被本规则误报
  - **整个附录模块缺失**（连「附    录」标题都没有）不归本规则，归 `9-整体` 的 `GLB-26`

### APP-01 · 文本

- **对象**：附录标题
- **期望**：`附    录`（「附」与「录」之间**正好 4 个半角空格**）
- **判定**：可见文本逐字符比较
- **来源**：规范文本框「一级标题，中间空4格，此页单独。」
- **说明**：识别锚点须**宽松**（按"去空白后等于 `附录`"匹配），否则空格数写错时会变成"找不到附录标题"

### APP-02 · 中文字体

- **对象**：附录标题
- **期望**：黑体
- **来源**：规范文本框「一级标题，中间空4格，此页单独。」+ 规范另处定义"一级标题：黑体，三号"

### APP-03 · 字号

- **对象**：附录标题
- **期望**：三号 = 16pt
- **来源**：同上

### APP-04 · 对齐

- **对象**：附录标题
- **期望**：居中
- **来源**：`heading 1` 样式（样张实测 `jc=center`）

### APP-05 · 后空行

- **对象**：附录标题段之后
- **期望**：正好 1 个空段落
- **判定**：空段落 = 段落内无文字、无图片、无域结果
- **依据**：规范文本框「空1行」；样张标题后恰有 1 个空段落

### APP-06 · 编号

- **对象**：附录子标题
- **期望**：`附录A`、`附录B`、`附录C`… **从 A 起，按字母序连续，不跳号、不重复**
- **判定**：按附录区内的子标题**出现顺序**取编号字母，检查是否为 `A, B, C, …` 的连续前缀
- **拒绝**：小写字母（`附录a`）、中文数字（`附录一`）、全角字母（`附录Ａ`）
- **边界**：编号必须是**手打文字**；子标题段落用了 Word 自动编号时由 `GLB-28` 报出，**本规则不重复报**（见 README「通用判定口径」第 10 条）
- **说明**：规范原文"论文的附录用大写字母A，B，C等连续编号，如附录A"
- **不做**：编号字母与题名之间是否加空格——规范未要求，**样张为「附录A名词术语及缩略词」（A 后无空格）**

### APP-13 · 大纲级别

- **对象**：附录子标题
- **期望**：大纲级别 **2 级**（样式 `heading 2`）
- **依据**：规范样张的「附录A名词术语及缩略词」为 `heading 2`；目录里该条为 `toc 2`（二级条目）
- **说明**：若级别不对，目录里会挂错层级。识别子标题仍以文本 `附录X` 为准，**不能用"找不到大纲级别 2 的段落"来代替本规则**

### APP-14 · 中文字体

- **对象**：附录子标题
- **期望**：黑体
- **判定**：只判**中文字符**所在的 run，读其**有效 `eastAsia` 槽**
- **样张实测**：`heading 2` 的 `eastAsia=黑体` → 合规

### APP-15 · 字号

- **对象**：附录子标题
- **期望**：四号 = 14pt（`w:sz=28`）
- **样张实测**：`heading 2` 的 `sz=28` → 合规

### APP-16 · 西文和数字字体

- **对象**：附录子标题
- **期望**：Times New Roman
- **判定**：只判 **ASCII 字母与数字**（`附录A` 的 `A` 要判），读其所在 run 的有效 `ascii` 槽；**排除标点**
- **与正文统一**：口径同 `5-正文` 的 `TXT-11`（二 / 三级标题的西文与数字用 TNR）
- **样张实测**：`heading 2` 样式的 `ascii` 为 `Arial`，但「附录A」所在 run 已**显式**写 `ascii/hAnsi=Times New Roman` → 生效值 TNR，**合规**

### APP-17 · 行距

- **对象**：附录子标题
- **期望**：1.5 倍
- **判定**：`lineRule="auto"` 时倍率 = `w:line / 240`（`360 → 1.5`）
- **样张实测**：`heading 2` 的 `spacing line=360 auto` → 合规

### APP-07 · 中文字体

- **对象**：附录正文（逐段检查，**不含附录子标题、不含图表题注**）
- **期望**：宋体
- **判定**：只判**中文字符**所在的 run，读其**有效 `eastAsia` 槽**；纯西文 run 不判中文字体
- **样张实测**：正文 run 未写 `rFonts`，`eastAsia` 继承 `Normal` 的宋体 → 合规

### APP-08 · 西文和数字字体

- **对象**：附录正文（逐段检查）
- **期望**：Times New Roman
- **判定**：
  1. 「字母、数字」= **ASCII 字母 `A–Z a–z` 与数字 `0–9`**，**不含标点**（`. , ? ( ) / ; :` 等排除）
  2. 对每个字母 / 数字字符，读其所在 run 的**有效 `ascii` 槽**，要求 = Times New Roman
- **样张实测**：正文里的 `A` `B` `C` `A1` `B2` `B3` 所在 run 未写 `rFonts`，`ascii` 继承 `Normal` 的 Times New Roman → 合规；全角 `，` `。` `；` 与半角 `( )` 均不参与本规则
- **说明**：同 `6-参考文献` 的 REF-07，**只判字母与数字**，避免标点误报

### APP-09 · 字号

- **对象**：附录正文（逐段检查）
- **期望**：小四 = 12pt（`w:sz=24`）

### APP-10 · 行距

- **对象**：附录正文（逐段检查）
- **期望**：1.5 倍
- **判定**：`lineRule="auto"` 时倍率 = `w:line / 240`（`360 → 1.5`）；为 `exact` / `atLeast` 时直接报出

### APP-11 · 首行缩进

- **对象**：附录正文（逐段检查）
- **期望**：2 字符
- **判定**：优先读 `w:ind/@firstLineChars`（单位 1/100 字符）；缺失时用 `@firstLine ÷ 字号` 换算
- **样张实测**：`firstLine="480" firstLineChars="200"` → 2 字符

### APP-12 · 对齐

- **对象**：附录正文（逐段检查）
- **期望**：两端对齐
- **样张实测**：正文未写 `w:jc`，继承 `Normal` 的 `jc=both`

## 不做

| 项 | 原因 |
|---|---|
| 附录**单独起页**（规范写"此页单独"） | 属「9 整体」作用域，已登记为 `GLB-25`（**本轮纳入**） |
| 附录中图、表、公式的序号冠以附录序码（图A1、表B2、式(B3)） | 属「5 正文」的图 / 表 / 公式规则（本轮未实现） |
| 附录正文字数、段数 | 内容规则 |
| 附录标题后空行以外，附录子标题与正文之间的空行 | 规范未要求（样张无） |
| 附录标题「此页单独」的**实际渲染效果** | 属通道 ②（需 PDF） |

## 来源说明

- **规范文字里有**：标题文本、"一级标题，中间空4格，此页单独"（→ 黑体 / 三号 / 居中 / 单独起页）、标题后空行、附录用大写字母连续编号
- **取自规范样张**：子标题为 `heading 2`（大纲级别 2 级、黑体 / 四号 / 1.5 倍）、附录正文的 宋体 / 小四 / Times New Roman / 1.5 倍 / 缩进 2 字符 / 两端对齐（规范未写附录正文格式，按"正文"类要求类推，与样张一致）
- **口径统一**：`APP-16`（子标题西文 = TNR）取自正文二级标题 `TXT-11`；样张原先此处为 `Arial`，**已改为显式 TNR**（见上）
- **规范样张的实测值**：附录标题 `jc=center`；子标题 run 的 `ascii/hAnsi=Times New Roman`（`heading 2` 样式本身仍为 `Arial`）、`eastAsia=黑体`、`sz=28`；正文 `spacing line=360 auto`、`ind firstLine=480 firstLineChars=200`、`sz=24`、无 `jc`（继承 `Normal` 的 `both`）
